## 一、结论先说：题目**现在拿不到**

| 观察 | 证据 |
| --- | --- |
| 登录后「答题」入口点不开 | **【实测】** 使用者当场试过：非实验时段点不进去 |
| 答题入口在**场次卡片**上，且受时间/出勤状态门控 | **【源证】** 前端：`exam(lesson) → $router.push('/exam/preparation/' + lesson.id)`；卡片显隐判断含 `exp.enableAttendance && exp.att_status.startsWith('att_y')`、时间锁 `lockPeriodStart` / `isBefore(lessonStartTime)` |
| 本次抓包 52 条请求里**没有任何**取卷请求 | **【实测】** grep `rpc/exam|preparation` 命中 0 |

⇒ **本题不是"扒接口就能提前拿到"的类型**：入口与后端都按「实验当场 + 出勤状态」开门。
另外，这是**计分**测试（`score_item` 含 `exp_preparation`，成绩字段 `project_score.preparation_score`），
所以「提前取题」既不合规、风险也直接落在成绩上 —— 本项目**不提供也未尝试**这条路径。

## 二、接口契约（**【源证】**，取自 `app.js`，可用于实验当天抓取）

| 步骤 | 接口 | 载荷 | 响应 |
| --- | --- | --- | --- |
| **取卷** | `POST {API}/rest/rpc/exam` | 表单 `user2project_id=<选课记录id>` | `{id, time, rules, questions[], status}` |
| 交单题 | `POST {API}/rest/rpc/submit_answer` | JSON `{exam_id, data:[...]}`，头 `Prefer: params=single-object` | — |
| 交卷 | `POST {API}/rest/rpc/submit_paper` | 表单 `user2project_id=<id>` | — |
| 重做 | `POST {API}/rest/rpc/reset_preparation` | JSON `{user2project_id:<id>}` | — |

页面路由：**`/exam/preparation/<user2project_id>`**（选课记录 id，**不是**场次 id）。

### 题目结构（前端消费的字段）

```
questions[i] = {
  orderNumber,             // 题号
  type,                    // 题型（服务端下发的中文串，如「单选题」）
  title,                   // 题干（含 <p> 等 HTML）
  student_answer,          // 你上次/当前的作答
  options: [ { key, label, prompt } ]
}
```

- 题号渲染格式：`orderNumber + '.（' + type + '）' + title`
- 作答控件由 `type` 决定（前端把 `options` 映射成 radio/checkbox/输入）
- `rules`：试卷规则文本；`time`：剩余时间（秒）→ **前端拿到就 `countdown()`**

## 三、场次级事实（**【实测】**，来自本次抓包的 `user2projects_ex` 响应）

| 字段 | 本次读到的值 | 含义 |

## 四、有没有「不触发计时」的只读取题路径？

- **有只读路径，但读不到题目**：正常页面加载就会内嵌读取
  `exams(*, remainTime:exam_remain_time)`（走 `rest/user2projects` 或 `rest/user2projects_ex`），
  这条**不触发计时**，但它返回的是**作答/成绩记录**（含每题得分），不是题库。
  **【实测】** 本次抓包里就有这两条查询（HTTP 200）。
- 试卷本体由 `rpc/exam` 在开放时按 `exam_paper_id` 组装下发。
- **【未验证】** 是否存在 `rest/<试卷表>?id=eq.<exam_paper_id>` 这类直接读卷的端点：
  本项目**登记但未去尝试**（原因见 §一）。如将来确认它可读，也只应用于**考后复习**。

## 五、实验当天的抓取与复习方案（推荐流程）

1. **实验前**：确认会话有效 —— `python run.py status`（token 有效期会打印出来，实测 **2 小时**）。
2. **到机位、入口开放后**：`python run.py recon` 打开受控浏览器（会自动带上已保存会话，通常免登录）。
3. 你自己点开「答题」页 → 工具把 `rpc/exam` 的**取卷请求与响应**（题目、规则、时长）完整录下来；
4. **作答仍然由你本人完成**（本项目不做代答、不做答案注入 —— 计分测试，且改的是你自己的成绩）；
5. 交卷后：另开终端 `python run.py stop` → 工具**优雅收尾并把 HAR 落盘**
   （⚠️ 别直接关窗口：实测「标签页关光但进程还在」会既不收尾、HAR 也不落盘，见 `ERROR.md` E6）；
6. `python run.py scrub <捕获.har>` → 脱敏（抹掉 Cookie / token / 登录体）后交给我分析。

**我拿到脱敏数据后能做的**：题目结构化、题型与分值统计、错题本（`student_answer` vs 正确判定）、
复习材料生成、成绩查询（`project_score`）、以及把整套流程固化进 `phyexp` 命令。
