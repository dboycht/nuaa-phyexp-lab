# 交付物语言说明

> 用途：把"本项目的交付物语言状况"写成**可执行的判据**，
> 避免后续会话把它误判成"缺少中文版"而白做一遍翻译。

## 一、结论

**本项目的全部说明文档与交付物均为中文**（`README.md` 中英混排，以中文为主并附英文标题）。
使用者即审核者，其评审语言为中文 ⇒ **不存在"缺少审核者语言版本"的缺口**。

## 二、逐项核对（可复核）

| 交付物 | 语言 | 位置 |
| --- | --- | --- |
| 项目说明 | 中文（+英文副标题） | `README.md` |
| 命令速查 | 中文 | `docs/使用手册.md` |
| 交付物清单与判据 | 中文 | `docs/交付说明.md` |

| 预习答题链路 | 中文 | `docs/答题链路.md` |

| 更新日志 | 中文 | `CHANGELOG.md` |
| 源码内注释与 CLI 输出 | 中文 | `src/phyexp_lab/**` |

## 三、为什么**不**再产出英文/第二语言版本

1. 规则 14 的要求是"**交付物必须包含审核者语言（中文）版本**"——
   该条件**已满足**，而不是"每个交付物都要多语言"；
2. 本项目是**个人研究 + 助手工具**（MIT 开源，单人维护），
   没有外部非中文审核者，二次翻译**不增加任何审查价值**，只增加"两份文档不一致"的风险；
3. 唯一的英文入口 `README.md` 承担"让外部读者看懂这是什么"的职责，**由英文标题与链接完成**，
   正文仍以中文为准 —— 这是**单一事实源**的刻意选择。

## 四、判据（可执行的一句话）

> **本仓库任何"说明性交付物"缺中文即为缺陷；反过来，已有中文版本的，
> 不因为"没有英文版"而算缺陷**（除非出现非中文审核者，届时再补）。

## 五、若将来确实需要英文版

按 `rules/14`（交付物语言）与 `physics-modelling-workflow` 的 R51 门禁思路来做：

1. 建 `docs/en/` 目录，**对照同一份中文源**翻译（而不是各写各的）；
2. 门禁判据（照 `AGENTS.md` 规则 14）：**目录存在 + 正文源文件够长（说明性 README 不算正文）
   + 已构建产物存在 + 产物不旧于任何源文件**；读不到就报"失明"，不许报"没问题"；
3. 记住其边界：门禁**拦得住"没有"，造不出内容，也判不了"翻译写全没写全、数字对不对"** ——
   后者只能靠人工对照审查。
