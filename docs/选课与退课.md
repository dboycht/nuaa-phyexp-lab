# 选课与退课（写操作）

> 本文件记录**写操作**的实测事实与再造流程。
> 证据分级沿用 [`接口逆向.md`](接口逆向.md)：**【实测】**= 真的发过请求；**【源证】**= 从线上前端读出的确定代码；**【待验】**= 尚未确认。

---

## 一、结论速查（2026-10-07 **实测**）

| 动作 | 接口 | 载荷 | 成功判据 |
| --- | --- | --- | --- |
| **选课** | `POST report-api/electives` | 表单 `lesson_id=<schedules.id>` + `course_id=<课程 id>` | HTTP 200 + `message=ok` **且** 回读到选课记录 |
| **退课** | `POST report-api/electives/<user2projects.id>/cancel` | 无 | 同上（成功文案**【待验】**） |
| **选实验项目** | `POST report-api/electives/project` | 表单 `course_id` + `project_id` | 同上 |

- 请求头：`Authorization: Bearer <jwt>`、`Content-Type: application/x-www-form-urlencoded`、
  `Referer: .../tianmuhu/wechat/login`，并带会话 Cookie（对齐前端 `withCredentials = true`）。
- `slot_id`（= `lesson_id`）是 **`schedules.id`**；退课用的 `user2project_id` 是 **`user2projects.id`**。
  两者**不是**同一个东西，退课时别传错（见 `docs/接口逆向.md` §3.4 判据 1/2）。

## 二、🔴 最反直觉的一条：成功时 `status` 是 `false`

实测选课成功，服务端原样返回：

```json
{"status":false,"code":200,"message":"ok"}
```

**成功却 `status:false`。** 因此本项目的判据是：

1. **只看 HTTP 状态码 + `message` 文案**，**绝不**用 `status` 字段判成败；
2. 代码里落地为 `api.classify_write()`（含回归用例：`{"status":false,...,"message":"ok"}` → `success`）；
3. **额外再往服务端核实一次**（见下节）—— HTTP 200 本身不构成"选上了"的证据。

**前端自己的处理方式也印证了这一点**：它对选课请求的成败判断是
「Promise resolve → 提示"选课成功"，reject → 提示"选课失败"」，
`reject` 只发生在 HTTP 401/400 等状态码上，**从未读过响应体里的 `status`**。

## 三、每次写操作都要"回读核实"（本项目纪律）

`python run.py elect --slot <id> --course <id>` 提交后会自动做两件事：

1. 重读 `rest/user2projects`，看**是否有对应 `schedule_id` 的记录**（有则打印 `user2project_id` 与退课命令）；
2. 重读 `rest/schedules?id=eq.<slot>`，对比 `current_student_number` 是否 **+1**。

两条都对上才算成功。**为什么非要这样**：写操作最危险的失败模式不是报错，而是
「脚本以为成功、服务端其实没动」—— 那种错误在抢课现场会让人错过补救窗口。

## 四、常用命令

```bash
python run.py elect --list                      # 只读：列出各课程「有余量」的场次（含余量/地点/是否已选）
python run.py mine                              # 只读：我的选课记录（含退课用的 user2project_id）
python run.py elect --course 71 --slot 4971 --dry-run   # 演练：只打印要做的事，不发写请求
python run.py elect --course 71 --slot 4971     # 真选课（写操作）
python run.py cancel --id <user2project_id> --dry-run  # 演练退课
python run.py cancel --id <user2project_id>            # 真退课（写操作）
```

**抢课引擎（定时提交）**

```bash
python run.py grab --course 71 --slot 4971 --in 20            # 演练：20 秒后"本应发射"
python run.py grab --course 71 --slot 4971 --at 12:30:00 --real   # 真提交（服务端时钟 12:30:00）
```

- `grab` **默认演练**；真实提交必须显式 `--real`（且 `--course` 或自动取"我的第一门课"）。
- 引擎参数已按本系统校准：预发射 **50ms**、最小间隔 **800ms**（依据见 `docs/接口逆向.md` §3.6）。

## 五、本机落地物（**不进仓库**）

| 路径 | 内容 |
| --- | --- |
| `%LOCALAPPDATA%\PhyExpLab\logs\write-<日期>.jsonl` | **每次写操作**：时刻 / 动作 / HTTP 状态 / 分类 / 服务端文案 |
| `%LOCALAPPDATA%\PhyExpLab\logs\grab-<时刻>.jsonl` | 抢课引擎每次**发射**：计划偏差毫秒 / HTTP 状态 / 服务端文案 |
| `%LOCALAPPDATA%\PhyExpLab\session\token.json` | Bearer token（**敏感**，2 小时过期） |

复盘只认这些日志：它们能区分「我以为成功」和「服务端说成功」。
