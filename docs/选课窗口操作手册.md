## 一、阶段 0：窗口开放前随时可做的自检

```powershell
cd D:\code\DeepSeekHarness\nuaa-phyexp-lab
$env:PYTHONIOENCODING='utf-8'

python run.py status        # 会话是否存在、token 有效期（实测约 2 小时）
python run.py probe         # 脚本直连是否可行（应看到带 token 的用例返回 200）
python run.py clock         # 对时（实测偏移约 +1.3s，本地慢）
python run.py snapshot      # 拉一次课程/项目/场次余量，确认能看到目标场次 id
```

**通过判据**：`probe` 里 `④ UA + Bearer token = 200`；`snapshot` 里能看到你要抢的场次 id。
**任一不通过**：先 `python run.py login` 重新登录（token 过期是常态，不是故障）。

## 二、阶段 1：窗口一开，**先抓一次真实提交**（窗口内、只做一次）

### 用户侧
1. 打开一个终端，运行：

   ```powershell
   python run.py recon --max-wait 900
   ```

2. 在弹出的 Chromium 里登录（学号 + 密码）。
3. **在窗口里手工完成一次真实的选课提交**（选中一个还有余量的场次，点提交/确认）。
   - 这一步是唯一能拿到写接口真实请求体的办法；
   - 只做**一次**，不要反复提交（避免把课表搞乱）。

### 收尾（重要，别直接关窗口）
4. 另开一个终端运行：

   ```powershell
   python run.py stop
   ```

   > 必须用 `stop` 触发优雅收尾，HAR 才会落盘；直接关窗口会丢 HAR（见 `ERROR.md` E6）。

5. 脱敏后再给我分析：

   ```powershell
   python run.py scrub "$env:LOCALAPPDATA\PhyExpLab\recon\capture-<最新>.har"
   ```

   `scrub` 会抹掉 Cookie / Authorization / 登录请求体（含密码 MD5）与敏感响应体，
   并**复检**是否还有残留（有残留会返回非 0）。

### 代理侧（我）
6. 从脱敏 HAR / JSONL 里提取写操作请求，确认四件事：
   - **URL 与 method**（预期 `POST {API}/report-api/electives`，需实测确认，可能是别的路径）；
   - **请求体字段**（是 `schedule_id`？还是 `{project_id, schedule_id, ordernumber...}`？是否表单编码？）；
   - **请求头**（是否需要额外的自定义头 / CSRF）；
   - **成功/失败/限速的响应文案**（这是结果判定 `Outcome` 的唯一依据）。

## 四、阶段 3：实现写接口（✅ 已于 2026-10-07 完成）

引擎给真实提交留的**注入点**如期生效，改动集中在装配处（引擎本身没动）：

```python
# src/phyexp_lab/api.py —— 写接口（不抛异常，统一返回 WriteResult）
def submit_booking(self, slot_id: str, course_id: Any) -> WriteResult:
    return self._post_form("report-api/electives",
                           {"lesson_id": str(slot_id), "course_id": str(course_id)}, ...)

# src/phyexp_lab/grabber.py —— 把 (slot_id, course_id) 适配成引擎要的 SubmitFn
submit_func = grabber.make_submit_func(client, course_id)
Grabber(client, cfg, submit_func=submit_func)
```

- **退课**路径实测为 `POST report-api/electives/<user2projects.id>/cancel`
  （**不是**原先推测的 `PATCH rest/user2projects`；PATCH 那套是教师端在用的）。
- CLI 侧新增：`elect`（选课/列清单）、`cancel`（退课）、`mine`（我的记录）。

## 五、阶段 4：演练（窗口外即可）

```powershell
# 先只看计划，核对目标时刻与换算是否正确
python run.py grab --slot <场次id> --in 60 --plan-only

# 再跑一次真定时（dry-run，不发写请求），确认发射精度
python run.py grab --slot <场次id> --in 20 --pre-fire 50 --max-attempts 3
```

**通过判据**：计划里"本地发射时刻 = 服务端目标 − 偏移 − 预发射量"；发射偏差在 ±5ms 内
（实测曾达 +0.1ms）。

## 六、阶段 5：实战抢课

```powershell
# 目标：服务端时钟走到 12:00:00 时提交场次 4864（可给多个，逗号分隔）
python run.py grab --course 71 --slot 4864 --at 12:00:00 --real
```

- `--course` **真实提交时必需**（写接口要 `lesson_id` + `course_id` 两个字段）；
  不传则自动取"我的第一门课"并打印出来。
- 不传 `--real` 就是演练：**不会发任何写请求**。

**更简单的临时抢课**（不挑时刻、直接提交一次）：

```powershell
python run.py elect --course 71 --slot 4864
```

纪律（写进代码也写在这里）：

- **先对时预热**（引擎自动做）；
- **提交间隔 ≥ 800ms**，命中限速指数退避 —— **不要为了快而调小**；
- 每次发射都落盘 `%LOCALAPPDATA%\PhyExpLab\logs\grab-*.jsonl`（含偏差毫秒、HTTP 状态、服务端文案），
  **事后复盘只认这个文件**，不认记忆；
- 结果四分类：成功 / 已满 / 被拒 / 限速；**超时与非预期响应一律记 `unknown`**，绝不当成功。

## 七、风险与回滚

| 风险 | 处置 |
| --- | --- |
| 抢错场次 | `python run.py mine` 找到 `user2project_id` → `python run.py cancel --id <id>` 撤回；**先确认撤销窗口是否还开着** |
| 触发限速 | 立刻停手，观察退避是否恢复；别硬顶 |
| token 中途过期（实测 2 小时） | 重新 `python run.py login`，再 `probe` 自检后继续 |
| 抓包丢了 HAR | 别关窗口，用 `python run.py stop`（`ERROR.md` E6） |
| 提交其实没成功但看起来成功 | **回读核实**：`elect` 已自动做（查 `user2projects` 是否有该 `schedule_id` + 余量是否 +1）；也认 `logs\write-*.jsonl` |
| 看到 `status:false` 就以为失败 | **成功时它就是 `false`**，别被骗；判据见 [`选课与退课.md`](选课与退课.md) §二 |
