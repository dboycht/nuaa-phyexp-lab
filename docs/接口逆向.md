## 二、鉴权链路

### 2.1 登录

```
POST {API_BASE}/rest/rpc/login
Content-Type: application/x-www-form-urlencoded
<body: code=<用户名/学号>&password=<MD5(明文密码)>
```

**【源证】** 前端登录页（`/tianmuhu/wechat/login`）模板含 `placeholder="用户名"` 与 `placeholder="密码" type="password"` 两个输入框，
提交时构造：

```js
var params = { code: user.username, password: MD5(user.password).toString() };
http.post("rest/rpc/login", params).then(function (response) {
  commit("login", response.data);
  if (response.data.role == "student" || ...) { ... }
});
```

- 密码是**前端 MD5 后**提交（非明文、非加盐，属于弱保护）；因此**脚本不需要明文密码**，只要能复用登录后的 token 即可。
- 登录页还有「记住我」：cookie `remenberMe`（值为 `用户名&密码`，**明文存 30 天**，见 `setCookie("remenberMe", ..., 60*24*30)`）→ 该 cookie 本身含凭据，**本项目绝不采集/保存它**（见 §五 脱敏纪律）。

**【源证】** 登录成功后的状态写入：

```js
state.isLogin = true; state.user = user;
localStorage.setItem("token", "Bearer ".concat(user.token));
if (location.pathname.endsWith("/wechat/login")) {
  if (user.not_safe) { /* 跳转 /changePassword 强制改密 */ }
}
```

- **登录成功判据（本项目采用）**：预约系统 origin 下 `localStorage.token` 非空且以 `Bearer ` 开头。
- 响应字段 **【待验】**：`token`（JWT）、`role`（`student`/`teacher`/…）、`not_safe`（密码强度不达标标记）、`id`、`code`、`name`（后四者由前端 `user.xxx` 使用推断）。
- ****【源证】** 请求拦截器**：所有后续请求自动带 `Authorization: <localStorage.token>`。

## 三、数据层（PostgREST）

### 3.1 语法（**源证**：真实抓到的查询串）

```
rest/user2projects?select=id,created_at,student:users!user2project_student_id_fkey(code,name),schedule_status,schedule_id=eq.<id>
rest/user_orgs?select=*,users(id,code,name)&users.role=eq.student&organization_id=eq.<key>
...&semester_id=eq.<id>&user_id=eq.<uid>&course_id=eq.<cid>&schedule_status=in.(elected,scheduled,free_schedule)
rest/user2projects_ex?select=*&schedule_id=eq.<id>&schedule_status=in.(elected,scheduled)&order=group_stamp,group_order,user_name
rest/course2projects?select=...&project_code=eq.<code>&organization_id=eq.<org>&status=eq.tmpl_release
```

- 等值：`col=eq.value`；取反：`neq.canceled`；集合：`in.(a,b,c)`；排序：`order=a,b`；投影：`select=a,b,c`；外键内嵌：`alias:table!fk_name(cols)`。
- **单对象**响应：请求头 `Accept: application/vnd.pgrst.object+json`（返回对象而非数组）。
- `PATCH`/`DELETE` 存在自定义网关兼容层 **【源证】**：当 URL 形如 `/xxx/...` 时会被改写为 `POST {BASE_URL}/xxx/post2rest/patch/...`；本项目用到的 `PATCH rest/...`（无前导斜杠）**不受该改写影响**，仍是 PATCH。

### 3.6 脚本直连可行性与延迟画像 —— **【实测】**（2026-09-21，`python run.py probe`）

对照组：对 `GET {API_BASE}/rest/time` 逐项加头，看**缺哪一样就不通**：

| 用例 | 状态 | 说明 |
| --- | --- | --- |
| ① 裸请求（无任何请求头） | **502 Bad Gateway** | 前置网关直接拒（连头都不给） |
| ② 浏览器 UA | **401** `{"code":"42501"}` | PostgREST `insufficient_privilege` ⇒ **请求已进 API，仅缺身份** |
| ③ UA + `Referer` | 401 | 同上（Referer 不是准入条件） |
| ④ UA + `Authorization: Bearer <jwt>` | **200** | ✅ **脚本直连可用** |
| ⑤ UA + Referer + token + Cookie | 200 | Cookie **非必需** |

> **结论（决定架构）**：抢课引擎**用 `requests` 直连即可**，不需要浏览器上下文。
> 浏览器（Playwright）只承担两件事：**登录**与**侦察抓包**。

**延迟画像**（同一 keep-alive 会话连发 8 次 `rest/time`）：

```
各次耗时(ms)：1250, 11, 12, 10, 11, 12, 16, 11
稳态（去掉首次）：最小 10 / 中位 11 / 最大 16
```

两条硬结论：

1. ⚠️ **必须预热连接**：首次请求要付 **1250ms**（TLS 握手 + 建连）。
   抢课若在 T-0 才第一次发请求，就等于开局先落后 1.2 秒 ⇒ 提交前必须先发一次「无关紧要的预热请求」。
2. ⚠️ **预发射提前量是 10–50ms 量级**，**不是** NUAA-Snatcher 在教务系统上实测的 100–300ms。
   ⇒ **移植过来的经验值必须在新系统上重新校准**（这正是本项目不直接抄旧参数的理由）。

**其它可用事实**

- `GET rest/time` 返回服务端时间（`[{"time":"2026-09-21T19:38:48.670291+08:00"}]`）
  ⇒ 可用于**本地时钟与服务端对时**；预发射要打的「T-0」应以**服务端时钟**为准。
- PostgREST 错误码 **`42501` = insufficient_privilege**（不带 token 时的标准应答），
  见到它说明「请求格式没问题，只是没登录」，不是接口地址写错。

### 3.7 只读采集实测（2026-09-21，`python run.py snapshot` / `watch`）

链路已跑通（**全部只读 GET**）：

```

   → 1 门课：id=71「大学物理实验Ⅰ(2)」

   → 24 个实验项目
slots(cid, pid)       GET rest/schedules?select=*,periods(*),locations(*),teacher:users!schedule_teacher_id_fkey(*),user2projects!user2project_schedule_id_fkey(*)
                          &is_publish=eq.true&project_id=eq.<pid>
                          &or=(course_id.is.null,course_id.eq.71)
                          &or=(is_reserved.eq.false,class_list.cs.{<org_id>},class_list.cs.{null})

   → 实测 48 条场次，其中 4 条有余量；容量 30/场（如笃行楼 501/502/506/515）
```

**实测踩坑（重要）**：`rest/rpc/*` 的**函数参数是裸值**，**不能**像表查询那样加 `eq.` 前缀 ——
写成 `user_id=eq.<本人 user_id>` 会得到：

```
HTTP 404 {"message":"Could not find the api.user_courses..."}
```

⇒ **判据：`rest/rpc/<fn>` 用裸值；`rest/<table>` 才用 `eq./in./gte.` 过滤器。**

**顺带读到的配置事实**

- `schedules` 行含 `current_student_number` / `max_student_number` ⇒ **余量 = 两者之差**（本项目 `Slot.remaining` 就是它）。
- 项目配置 `score_item` 实测为
  `[{"item":"exp_preparation","label":"实验预习","weight":0.2}, {"item":"exp_report","label":"实验报告","weight":0.8}]`
  ⇒ **预习答题占总评 20%**（与 §3.5 的"计分"结论一致）。
- 项目字段 `pre_list`（预习列表）在该项目上为 `[]`；它是否承载预习题目**【待验】**。

**时钟偏差（【实测】，已用严格对时确认）**：`python run.py clock` 用 7 次 `rest/time` 往返、
按 `offset_i = server_time_i − (t0_i + rtt_i/2)` 取中位数：

```
服务端 − 本地 = +1.300s（本地慢 1.300s）；RTT 最小 9ms / 中位 11ms；7 次采样，离散度 8ms
```

⇒ **本地钟稳定地慢约 1.3 秒**（早先单次采样的"约 2 秒"是含 RTT 的粗略值）。
抢课打点必须换算到服务端时刻：本地发射时刻 = 服务端目标时刻 − 偏移 − 预发射提前量。

**发射精度（【实测】，`python run.py grab --in N` 演练）**：定时循环采用"粗睡到点前 0.2s + 短睡精调"，
实测首次发射的**计划偏差 +0.1ms**，后续重试严格落在 +800.2ms / +1600.5ms（间隔参数生效）。

## 四、复现本文档的方法（供后续会话照做）

1. 抓前端：`https://phyexp.nuaa.edu.cn/tianmuhu/wechat/login` 的 HTML 里有三个 JS 入口；
2. 下载 `manifest/vendor/app.<hash>.js`；
3. ⚠️ **不要直接 grep**：这三个文件是**压缩成单行的**，一次匹配会吐出上百 KB 的整行、把上下文撑爆。
   正确做法是**用正则抽取匹配子串**再落成小文件阅读，例如：
   - `["'](/[A-Za-z0-9_\-/\.\{\}\$:]{2,90})["']` → 路由/路径字面量
   - `rest/([a-z_][a-z0-9_]{2,40})` → 表名
   - `\.(post|patch|put|delete)\(\s*['"]([^'"]{1,140})['"]` → 写操作接口
   - `(?s).{0,120}(baseURL|axios\.create).{0,160}` → 请求基址与拦截器（**必须加 `(?s)`**，否则 `.` 不跨行、匹配为 0）
4. 交互式验证：`python run.py recon`（本人登录 + 记录 HAR）。

## 五、脱敏与合规纪律（本项目实现约束）

1. **不采集 `remenberMe` cookie**（它明文含用户名与密码）；`recon.py` 对 Cookie / `Authorization` / `Set-Cookie` 的值只记录长度。
2. 命中 `authserver|login|sso|cas|passport|captcha|verify|password` 的 URL，**不记录请求体与响应体**。
3. 账号密码**绝不经过脚本**：登录始终由使用者本人在弹出的浏览器窗口完成。
4. 提交类请求遵守低频 + 限速退避（默认最小间隔 800ms，见 `grabber.GrabConfig`），不做高频轰炸。
5. 仅供个人学习使用，遵守学校相关管理规定。
